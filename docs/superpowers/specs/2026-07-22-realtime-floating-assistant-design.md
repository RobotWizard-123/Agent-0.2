# 全站实时反馈悬浮 AI 助手设计规格

日期：2026-07-22
状态：已完成交互式设计确认，待书面审阅

## 1. 目标

在现有 L5-A2-08 机房管理网站中增加一个全站可用的悬浮 AI 助手。助手自动读取机房总览、机柜与设备、容量、链路、告警、方案、执行结果、审计及服务健康状态，并在重要状态变化后主动提醒用户。

管理员可以通过对话生成受约束的上架或处置方案，但任何真实状态变更仍必须经过现有的唯一一次最终确认。只读用户只能查询、解释和诊断。

本功能接入兼容 OpenAI Chat Completions 的私有模型 API。密钥只存在于服务端环境变量中，不得出现在浏览器、应用响应、日志、源码或 Git 历史中。

## 2. 已确认的产品决策

- 助手自动读取整个网站的结构化上下文，而不是抓取页面 DOM。
- 采用服务端上下文编排方案；模型负责理解与解释，确定性规则引擎负责约束与准入。
- 浏览器每 8 秒轮询一次，允许实现落在 5–10 秒范围内。
- 主动提醒新告警、容量达到 80%、硬约束阻断、采集或模型离线、方案执行成功或失败。
- 管理员可生成待确认方案；只读用户只能查询、解释和诊断。
- 对话仅在当前登录会话中保存，退出登录后清除；生成的方案、执行结果和最终确认继续进入正式审计。
- 不允许从聊天文本直接执行动作，所有执行仍使用唯一一次最终确认。

## 3. 范围与非目标

### 3.1 本次范围

- 全站悬浮入口、聊天面板、主动提醒角标和站内跳转。
- 服务端全站上下文汇总、会话内对话存储和反馈差异检测。
- 兼容 OpenAI API 的通用对话调用与严格输出校验。
- 基于角色的查询、提案和方案生成权限。
- 复用现有计划、规则校验、确认、执行、回滚与审计闭环。
- 模型不可用时的确定性查询与提示降级。

### 3.2 非目标

- 不实现 WebSocket 或 SSE；实时性由 5–10 秒轮询提供。
- 不永久保存完整对话，不建设聊天记录管理后台。
- 不实现模型直接自动执行、低风险免确认或批量自动确认。
- 不建设向量数据库、Embedding 或通用 RAG 平台。
- 不抓取原始 DOM，不向模型发送密码、Cookie、API Key 或其他服务端机密。
- 不在本阶段接入 NetBox 或真实采集器；继续通过既有适配层预留替换点。

## 4. 总体架构

### 4.1 AssistantContextService

该服务从版本化状态仓库构建一个语义完整的全站快照，覆盖当前网站所有业务区域：

- 房间与供电总览；
- 22 个机柜的设计功率、已用功率、U 位、重量、端口及风险；
- 机柜内设备和服务器详情；
- 已核实的电源与网络链路，以及明确标记为未知的链路；
- 当前告警、诊断、处置状态；
- 计划、确认、执行、回滚和变更结果；
- 最近审计摘要；
- 采集器、模型和应用健康状态；
- 当前用户角色；
- 浏览器补充的当前路由、选中对象和筛选条件。

服务端始终掌握完整业务状态。为控制模型上下文大小，发送给模型的提示包含全站索引、所有活动风险、全站容量摘要、当前选中对象详情及与问题相关的实体详情；历史审计仅发送最近且相关的摘要。任何被省略的历史原始记录仍可由服务端按实体重新检索，不以 DOM 内容替代。

### 4.2 AssistantOrchestrator

该组件负责：

- 以当前登录会话为键维护最近 20 轮用户—助手对话，最多 40 条聊天消息；主动提醒不计入该上限；
- 组合固定系统指令、全站上下文、UI 上下文和用户问题；
- 调用兼容 OpenAI 的 `/v1/chat/completions` 接口；
- 校验模型返回的结构化结果；
- 生成安全的回答、证据引用和可选动作提案；
- 对模型超时、限流、非 JSON 响应或非法动作进行降级处理。

同一会话只允许一个在途模型请求。服务端对请求进行频率限制，初始规则为每个会话每分钟最多 10 次聊天请求；反馈轮询不计入模型请求，也不会触发模型调用。

### 4.3 FeedbackDetector

该组件以状态版本、依赖健康快照和会话游标为基础比较状态变化，确定性地产生反馈事件。首次同步把当前活动风险作为基线投递一次，后续只投递新出现或发生状态迁移的事件。事件类型包括：

- `alarm_opened`：出现新告警；
- `capacity_warning`：机柜功率、U 位、重量或端口首次达到 80% 告警线；
- `constraint_blocked`：新方案或请求被硬约束阻断；
- `dependency_offline`：采集器或模型由可用转为离线/降级；
- `plan_succeeded`：方案执行成功；
- `plan_failed`：方案执行失败或回滚。

事件 ID 由实体、事件类型和状态版本稳定生成。每个会话记录已投递游标，因此重复轮询不会重复提醒；恢复连接后根据游标补齐未读事件。

### 4.4 AssistantActionBridge

模型只允许返回以下高层意图：

- `answer`：回答与解释；
- `navigate`：建议跳转到站内实体；
- `propose_placement`：生成上架方案请求；
- `propose_remediation`：生成告警处置方案请求。

动作桥接层不得直接修改状态。管理员接受提案后，桥接层把提案转换为现有计划服务的输入，随后按原流程执行：

`计划生成 → 规则校验 → 展示风险与容量影响 → 唯一一次最终确认 → 模拟执行 → 验证 → 审计`

设备尺寸、额定功率、实时功率、重量、端口、机柜设计容量和规则结果均属于不可由模型改写的事实。只读用户请求任何提案动作时返回权限拒绝，但仍可获得解释性回答。

## 5. API 设计

### 5.1 发送消息

`POST /api/assistant/messages`

请求：

```json
{
  "message": "CAB-09 还能上架一台 4U 服务器吗？",
  "ui_context": {
    "route": "rack",
    "entity_id": "CAB-09",
    "filters": {}
  }
}
```

响应：

```json
{
  "message_id": "MSG-...",
  "answer": "...",
  "evidence": [
    { "type": "rack", "id": "CAB-09", "label": "CAB-09" }
  ],
  "proposal": null,
  "model_status": "available",
  "state_version": 42
}
```

`proposal` 存在时只代表一个待用户接受的提案，不代表已创建或已执行计划。

### 5.2 获取会话消息

`GET /api/assistant/session`

返回当前登录会话内最多 20 轮用户—助手对话和未读提醒。用户退出登录时，服务端删除对应会话数据。

### 5.3 轮询反馈

`GET /api/assistant/feedback?cursor=<cursor>&route=<route>&entity_id=<id>`

响应包含 `events`、`next_cursor`、`state_version` 和 `synced_at`。浏览器默认每 8 秒调用一次；页面隐藏时可以降低频率，恢复可见后立即同步。

### 5.4 接受提案并生成方案

`POST /api/assistant/proposals/:id/plans`

仅管理员可调用。服务端根据最新状态重新构建请求、执行现有规则计算并返回标准计划。该接口不能确认或执行计划。

最终确认继续使用现有计划确认接口，确保整个系统只有一个执行确认入口。

## 6. 模型输出约束

模型响应必须解析为如下逻辑结构：

```json
{
  "answer": "面向用户的中文回答",
  "evidence": [
    { "type": "rack", "id": "CAB-09" }
  ],
  "intent": {
    "type": "answer"
  }
}
```

服务端验证：

- `answer` 必须是有长度上限的纯文本；
- `evidence` 中的实体必须真实存在且当前用户有权读取；
- `intent.type` 必须在允许列表内；
- 提案中的设备事实必须来自用户明确输入或服务端已有事实；
- 模型不得修改规则结果、状态版本、确认次数或执行状态；
- 非法响应转换为稳定错误码，并切换到确定性降级回答。

## 7. 悬浮窗界面

- 右下角显示“AI 助手”悬浮按钮。
- 有新反馈时显示严重度颜色和未读数量角标，并出现短时、不遮挡业务操作的提示。
- 展开后使用约 `420 × 640px` 的悬浮侧面板；窄屏切换为全屏抽屉。
- 顶部显示全站上下文同步状态、状态版本、模型状态和用户权限。
- 主区域按时间混合展示用户消息、助手回答和主动提醒。
- 回答中的证据以安全标签展示；点击后通过现有路由跳转到机柜、告警、链路、方案或审计页面。
- 提案使用独立卡片展示动作、容量变化、风险、阻断项和证据。
- 管理员可点击“生成待确认方案”；只读用户看到只读说明且没有写操作按钮。
- 最小化不停止轮询；退出登录清空对话和未读状态。
- 所有模型文本使用 `textContent` 或等价安全方式渲染，不接受模型 HTML。

## 8. 权限与安全

- 复用现有管理员和只读角色，不引入第三种角色。
- API Key、模型地址和模型名称只从 `AGENT_BASE_URL`、`AGENT_API_KEY`、`AGENT_MODEL` 和 `AGENT_TIMEOUT_MS` 读取。
- `/api/config/status` 只暴露是否已配置和模型显示名，不返回地址或密钥。
- 聊天写请求继续执行登录校验、角色校验和同源校验。
- 用户消息被当作不可信数据放入用户消息区，不得拼入系统指令。
- 服务端不发送密码、Cookie、会话签名、API Key、内部堆栈或未授权实体。
- 模型返回的导航、实体引用和提案均由服务端重新查验。
- 当前曾通过截图暴露的 API Key 只可用于本地演示；远程部署前必须轮换。

## 9. 降级与错误处理

- 模型未配置：聊天区显示“规则引擎接管”，支持容量、链路、告警和方案状态的确定性查询。
- 模型超时或离线：本次请求返回降级回答和稳定错误码，主网站不受影响。
- 模型响应无效：忽略非法动作，不展示未经验证的提案。
- 反馈轮询失败：显示“上下文同步中断”，采用退避重试；恢复后利用游标补齐事件。
- 状态版本变化：提案转计划时按最新状态重算；已生成计划在确认时继续使用现有乐观并发校验，过期则拒绝。
- 请求过快：返回 `ASSISTANT_RATE_LIMITED` 和可重试时间。
- 会话过期或退出：立即清除内存对话，前端返回登录状态。

## 10. 测试与验收

### 10.1 单元测试

- 全站上下文覆盖所有业务区域且不包含敏感字段；
- 上下文裁剪保留活动风险、全站摘要和当前实体；
- 反馈事件检测、稳定 ID、游标补发及去重；
- 20 轮会话上限和退出清除；
- 模型响应结构、证据实体和动作白名单校验；
- 确定性降级查询；
- 管理员与只读角色权限。

### 10.2 API 集成测试

- 登录后聊天、会话查询和反馈轮询；
- 未登录拒绝、跨源拒绝和只读写操作拒绝；
- 模型成功、超时、HTTP 错误、无效 JSON 和非法动作；
- 提案转换为标准计划；
- 状态版本冲突时重新计算或拒绝；
- API 响应不泄露模型地址、密钥或会话秘密。

### 10.3 浏览器端到端测试

- 打开、最小化和恢复悬浮窗；
- 查询机柜、容量、链路和告警，并展示可跳转证据；
- 触发功率告警后在下一次轮询周期内收到主动提醒；
- 点击提醒跳转到对应页面；
- 管理员从对话提案生成方案并完成唯一一次最终确认；
- 只读用户可以问答但无法生成方案；
- 模型离线时显示规则降级且基础查询可用；
- 退出登录后对话清空。

### 10.4 完成标准

- 使用私有兼容 OpenAI API 完成一次真实模型回答；
- API 离线时所有既有页面和确定性管理闭环继续工作；
- 主动提醒延迟在正常本地环境下不超过一个 8 秒轮询周期加一次网络往返；
- 所有新旧自动化测试通过；
- 源码、Git 差异、浏览器网络响应和应用日志均不含 API Key。

## 11. 部署与运行

- 本地通过 `.env` 配置模型，`.env` 保持 Git 忽略。
- Docker 与远程服务器继续通过环境变量或受控 Secret 注入模型配置。
- 助手会话和反馈游标初期保存在 Node 进程内存中；单实例演示部署满足要求。
- 后续扩展到多实例时，将会话与游标适配到 Redis，不改变前端 API。
- NetBox 与真实采集器接入后，只替换上下文数据提供者，不改变悬浮助手、权限或最终确认协议。
