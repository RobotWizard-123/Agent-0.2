# 统一重配置迁移与层内整理设计

## 状态

- 日期：2026-08-07
- 状态：设计已分节确认，等待规格文档最终审阅
- 范围：同规格批量服务器部署、既有服务器迁移、连接资源分配、服务器取出后的单挡板层整理

## 背景与现状问题

当前部署规划把直接上架、挡板调整和迁移拆成了不同流程。迁移仅在没有直接候选时作为兜底，并且只接受 `count = 1`、每个方案只迁移一台既有服务器。这造成以下问题：

- 直接部署与迁移方案不能在同一评分体系中比较，可能保留较差的空间碎片。
- 同规格批量服务器不能通过迁移既有服务器获得整体可行方案。
- `move_device` 只修改机柜、挡板层和 U 位，不会同步更换 PDU 插口与交换机端口，可能产生位置与连接记录矛盾。
- 固定设备数量上限把合法请求提前拒绝，不能根据实际求解规模决定是否受理。
- 服务器取出后，同一挡板层中更高 U 位的服务器保持原位置，形成不必要的空洞和视觉上的悬空。

## 目标

1. 用一个统一重配置问题模型表达直接部署、批量部署和既有服务器迁移。
2. CP-SAT 与 Beam Search 消费相同的槽位、容量、连接和迁移约束。
3. 常规情况下统一比较直接部署、迁移一台和迁移两台的方案。
4. 常规范围无解时，自适应考虑迁移三台及更多合格服务器，不设置固定迁移台数上限。
5. 对同规格批次一次规划、一次确认、原子执行；任何一步失败时不保留部分结果。
6. 跨机柜迁移自动分配目标 PDU 插口与交换机端口，并检查实际资源冲突。
7. 服务器取出后，在其原挡板层内稳定向下紧凑整理，不跨挡板。
8. 移除固定的单次部署台数上限，以 20,000 个分配变量作为统一计算预算。

## 非目标

- 本阶段不支持同一请求中包含不同 U 高度、功率、重量或端口规格的混合批次。
- 本阶段不执行真实物理搬迁、断电、布线或交换机配置；执行适配器仍以当前模拟基础设施为边界。
- 本阶段不自动调整挡板位置，也不允许层内整理跨越挡板边界。
- 本阶段不改变既有服务器的测量事实、业务归属、关键级别、可迁移标记或维护窗口。
- 本阶段不因求解困难自动拆分批次或部分部署。

## 核心决策

### 统一重配置规划器

规划主流程调整为：

```text
规范化请求
  -> 构建统一重配置问题
  -> 检查 20,000 变量预算
  -> CP-SAT 求解
  -> Beam Search 技术回退
  -> 确定性约束复核
  -> 统一评分、去重并保留最多 4 个候选
  -> 一次确认
  -> 原子执行或整体回滚
```

`migration-planner.js` 不再作为独立的单台兜底规划器。其迁移资格、影响分析和迁移成本能力并入统一问题构建器、两个求解器和公共评分器。规划器不放宽确定性约束，求解结果只有通过公共复核后才能成为候选方案。

### 同规格批次展开

请求仍采用一个设备模板和 `count`，但规划前展开为稳定、唯一的逻辑设备实例。每台实例继承相同规格，并获得确定性 ID。全部实例都必须分配到合法位置和连接资源，否则该候选整体无效。

`count` 只要求是正整数，不设置固定最大值。前端输入、HTTP 校验和领域校验均不得再使用 `max = 10`、`max = 100` 或其他固定台数限制。

### 统一问题模型

问题模型至少包含：

- 待部署的同规格设备实例。
- 所有服务器机柜、挡板层、合法连续 U 位和保留 U 位。
- 固定既有设备与符合迁移资格的既有设备。
- 机柜设计功率、承重、端口容量和角色。
- 可用 PDU、PDU 插口、交换机、交换机端口及其故障域。
- 既有电源、网络连接和需要保留的设备侧端口、VLAN 属性。
- 副本组、电源故障域、网络故障域和业务邻近信息。
- 当前状态版本及用于计划陈旧检测的规划指纹。
- 策略权重、候选上限、时间预算和 20,000 变量预算。

每个可选位置必须绑定一个确切的连接资源组合。资源组合包含满足设备需求的空闲 PDU 插口和交换机端口；同一候选内的不同设备不能共享同一独占资源。求解器选择的是“位置 + 连接组合”，而不是只判断机柜端口总数。

### 连接资源清单

现有网络拓扑已经提供接入交换机的 `downlink_ports`，但 PDU 只有机柜上的 `pdu_ids`，没有可用插口总数。为避免运行时猜测，本设计要求把连接容量提升为明确资源清单：

- 在电源拓扑中为每个 PDU 保存 `id`、`rack_id`、`source_id` 和 `outlet_count`。
- 交换机继续使用 `id`、`connected_rack_ids` 和 `downlink_ports`。
- PDU 插口按 `P01` 至 `P{outlet_count}` 枚举；交换机端口按当前命名约定从 `GE0/0/01` 枚举到 `downlink_ports`。
- PDU 资源键是 `(pdu_id, outlet)`，网络资源键是 `(switch_id, switch_port)`；这两个组合必须全局唯一。
- 连接记录中的 `rack_id`、`source_id` 必须与目标 PDU、机柜和交换机拓扑一致。

现有演示种子必须显式补齐每个 PDU 的 24 个插口，并保留已经占用的 `Pxx` 记录；这只是一项数据迁移，不作为运行时默认值。非演示状态如果缺少 PDU 容量、交换机端口容量或引用了清单外资源，规划应返回 `LINK_RESOURCE_INVENTORY_INVALID`，不得假设容量或创建无限端口。

## 两阶段迁移搜索

### 第一阶段：常规统一搜索

第一阶段允许每个候选迁移零台、一台或两台合格的既有服务器。直接部署和迁移部署进入同一候选池，使用相同约束和最终评分，不再采用“有直接候选就跳过迁移”的流程。

迁移仍然有成本，因此在其他收益接近时优先直接部署或较少迁移；但如果一次小规模迁移能显著改善容量水位、空间连续性或业务布局，它可以排在直接部署之前。

### 第二阶段：自适应扩展迁移

仅当第一阶段没有任何通过确定性复核的完整批次候选时，才启动扩展迁移：

- 搜索范围从迁移三台开始。
- CP-SAT 可以使用全部合格可迁移设备，并以迁移数量最少作为首要目标，再在该最少迁移层级内优化策略得分。
- Beam Search 按迁移深度 3、4、5 依次扩展；在某一深度找到合法完整批次候选后，不再搜索更大的迁移深度。
- 不设置新的固定迁移台数上限；实际范围受合格设备数量、求解时间和 20,000 变量预算约束。
- 迁移三台及以上的候选标记为 `expanded_migration` 和高影响，界面必须明确显示迁移台数及设备清单。

第一阶段的 CP-SAT 技术故障由 Beam Search 完整执行第一阶段；第二阶段的 CP-SAT 技术故障由 Beam Search 从迁移深度三开始回退。CP-SAT 返回“无解”不是技术故障，应进入下一迁移阶段，而不是跳过业务流程。

### 迁移资格

跨机柜迁移的既有服务器必须同时满足：

- `movable = true`
- `criticality != critical`
- 存在有效 `maintenance_window`

迁移后必须重新满足 U 位、功率、重量、端口、机柜角色、10U 层限制、副本故障域及所有连接资源约束。求解器不能修改资格字段来制造可行解。

## 变量预算

统一问题构建完成后、调用任一求解器前，按实际候选分配变量数量进行估算。预算包括新设备位置及连接组合、可迁移设备的保留或目标组合，以及资源互斥所需的主要分配变量。

- 估算值不超过 20,000：允许进入求解。
- 第一阶段已经超过预算：立即返回 `MODEL_BUDGET_EXCEEDED`。
- 第一阶段无解、第二阶段扩大迁移后超过预算：返回 `MODEL_BUDGET_EXCEEDED`。
- Beam Search 不得绕过相同预算继续运行。
- 系统不截断设备数、不静默缩小迁移集合，也不自动执行部分批次。

错误响应提供请求台数、估算变量数、预算值及“拆分批次后重试”的用户提示，但不得暴露完整求解输入。

## 约束与评分

### 硬约束

以下条件作为硬约束，任何评分都不能覆盖：

- 每台新设备必须且只能获得一个合法连续 U 位。
- 设备之间不得重叠，不得占用保留 U 位，不得越过挡板边界。
- 服务器只能进入服务器机柜，10U 设备仍只能进入 L01，设备 U 高度仍受现有支持范围限制。
- 投影后的功率、重量和端口占用不得超过机柜容量。
- PDU 插口和交换机端口必须存在、可用且在候选内唯一。
- 副本组不得违反电源和网络故障域规则。
- 跨机柜移动必须满足迁移资格。
- 同规格批次必须全部成功分配。

### 统一评分

通过硬约束的候选继续使用策略配置中的容量水位、业务邻近、空间连续性、链路邻近、碎片空间和故障域指标，并新增：

- 迁移台数成本。
- 迁移距离或跨机柜影响成本。
- 连接重分配成本。
- 受影响业务数量和维护窗口成本。

最终分数越低越优。第一阶段对零至两台迁移方案统一评分；第二阶段先按迁移台数最少进行词典序优化，再比较同一最少迁移层级中的统一分数。并列时依次选择迁移更少、涉及机柜更少、连续空间更好、稳定 ID 顺序更小的候选，保证相同输入得到稳定排序。

最多返回 4 个不重复候选，不使用重复方案补足数量。

## 动作与连接模型

### 新设备放置

`place_device` 必须携带服务端生成的确切连接分配：

```json
{
  "type": "place_device",
  "rack_id": "CAB-02",
  "layer_id": "L02",
  "start_u": 13,
  "device": { "id": "SRV-NEW-001" },
  "power_connections": [
    { "source_id": "JG1", "pdu_id": "CAB-02-PDU", "outlet": "P07" }
  ],
  "network_connections": [
    { "device_port": "eth0", "switch_id": "ASW-01", "switch_port": "GE0/0/19", "vlan": "VLAN-20" }
  ]
}
```

连接数量由请求规格和当前连接约定决定；每个网络设备侧端口都必须映射到唯一交换机端口。

### 既有设备完整重定位

跨机柜 `move_device` 是完整重定位动作，而不是单纯的位置修改。动作包含受保护的来源快照、目标位置和目标连接：

```json
{
  "type": "move_device",
  "device_id": "SRV-017",
  "from": {
    "rack_id": "CAB-01",
    "layer_id": "L02",
    "start_u": 13
  },
  "to": {
    "rack_id": "CAB-03",
    "layer_id": "L01",
    "start_u": 2
  },
  "power_connections": [],
  "network_connections": []
}
```

执行时校验 `from` 仍与当前状态一致，释放该设备的旧 PDU 与交换机端口，再写入目标位置和新连接。网络连接应保留设备侧端口与 VLAN 等业务属性，只替换目标交换机及端口；电源连接按目标机柜资源重新生成。任何旧连接未释放、新连接冲突或连接数量不足都会使整个计划失败。

动作只能由服务端已持久化的计划生成。Agent 和浏览器可以选择候选，但不能自行编写 PDU、交换机、U 位或迁移动作。

## 原子执行与计划生命周期

一个候选中的所有迁移、旧连接释放、新连接分配和新设备放置构成一个事务：

1. 根据状态版本和规划指纹检查计划未陈旧。
2. 在状态副本上按动作顺序生成完整投影。
3. 对投影状态运行公共确定性约束复核。
4. 复核通过后一次性提交设备和连接状态。
5. 任一步失败时不提交投影；若执行适配器已经产生模拟步骤，则按计划中的补偿信息整体恢复。

不允许仅迁移部分既有服务器、仅放置部分新服务器或保留一半连接变更。候选切换和最终确认继续使用计划 ID；机柜、设备、PDU、交换机端口、连接或状态版本变化时，返回 `PLAN_STALE`，前端清除失效候选并要求重新规划。

计划模式升级到新的 schema 版本。升级前持久化且不包含完整连接分配的旧计划不能执行，应作为陈旧计划处理，而不是尝试补全后继续执行。

## 服务器取出后的层内整理

### 边界

被取出的目标服务器仍执行现有删除资格与业务安全校验，包括目标设备本身的可操作性、关键级别、维护窗口和副本风险。这里的“不检查迁移条件”仅适用于删除后被动向下整理的其余服务器。

整理范围严格限制在目标服务器删除前所在的同一机柜、同一挡板层。不得移动其他层、不得调整挡板、不得跨机柜。

### 确定性整理算法

1. 记录目标设备删除前的机柜和挡板层。
2. 删除目标设备以及属于它的电源、网络连接。
3. 取得该层中所有未取消的剩余设备，按 `start_u` 升序、设备 ID 升序稳定排序。
4. 从该层最低合法 U 位开始维护放置游标。
5. 对每台设备选择不低于游标的最小连续合法区间；跳过保留 U 位，并保证整个设备留在原层内。
6. 新 `start_u` 不得高于该设备原 `start_u`，设备相对顺序不得改变。
7. 更新发生变化的 `start_u`，不更改机柜、挡板层、PDU、交换机、业务字段或迁移资格字段。
8. 对删除和全部下移动作的最终状态进行一次完整复核，再原子提交。

层内下移属于删除事务的派生整理动作，不使用跨机柜 `move_device`，也不运行 `movable`、关键级别或维护窗口校验。如果算法不能在原层形成合法布局，则返回 `COMPACTION_FAILED`，删除和全部下移均不提交。

计划、影响摘要和审计记录必须列出每台被动下移服务器的原 `start_u` 与新 `start_u`。

## 错误与诊断

| 错误码 | 含义 | 用户处理 |
| --- | --- | --- |
| `MODEL_BUDGET_EXCEEDED` | 当前批次或扩展迁移模型超过 20,000 变量 | 拆分批次后重新规划 |
| `NO_RECONFIGURATION_PLAN` | 扩展迁移搜索在预算内完成后仍无完整方案 | 调整容量、维护窗口或部署规格 |
| `LINK_RESOURCE_EXHAUSTED` | 合法位置存在，但 PDU 或交换机端口无法完整分配 | 释放或扩充连接资源 |
| `LINK_RESOURCE_INVENTORY_INVALID` | PDU 或交换机资源清单缺失、不一致或引用越界 | 修复拓扑资源清单后重试 |
| `MIGRATION_WINDOW_REQUIRED` | 需要迁移但相关设备没有有效维护窗口 | 配置维护窗口后重试 |
| `PLAN_STALE` | 计划依赖的设备、位置或连接资源已经变化 | 清除旧候选并重新规划 |
| `EXECUTION_ROLLED_BACK` | 执行步骤失败，状态已恢复 | 查看失败步骤后重新规划 |
| `COMPACTION_FAILED` | 删除后的原挡板层无法形成合法紧凑布局 | 修复机柜布局数据后重试删除 |

`NO_RECONFIGURATION_PLAN` 只能在第二阶段已完成且未超过模型预算时返回。迁移两台仍无解不能直接触发该错误。无解响应应附带聚合后的拒绝原因和迁移资格评估，不暴露求解器堆栈或完整基础设施快照。

## 前端行为

- 设备数量输入移除固定 `max`，仍要求正整数。
- 超过计算预算时显示拆分批次提示，不自动改小数量。
- 候选卡片显示新增设备数、迁移台数、受影响业务、维护窗口及连接重分配摘要。
- 三台及以上迁移显示“扩大迁移范围/高影响”标识。
- 用户仍只需选择一个候选并确认一次。
- `PLAN_STALE` 或 `PLAN_NOT_FOUND` 后立即清除当前候选，禁止重复提交失效计划。
- 服务器取出结果显示同层下移设备数量，并可在审计详情查看前后 U 位。

## 审计要求

计划生成、候选选择、执行和回滚记录至少包含：

- 求解阶段、求解引擎、状态、耗时、模型变量估算和回退原因。
- 迁移范围是常规阶段还是扩展阶段。
- 新设备的最终机柜、挡板层、U 位和连接资源。
- 迁移设备的来源、目标、旧连接、新连接、维护窗口和受影响业务。
- 被删除设备及其释放的连接。
- 被动下移设备的原始和最终 `start_u`。
- 确定性复核结果、失败错误码和整体回滚结果。

日志不得记录环境凭据、求解器完整输入或未脱敏的敏感配置。

## 测试设计

### 公共问题模型与求解器

- 同一问题模型可分别供 CP-SAT 和 Beam Search 使用。
- 第一阶段产生零、一、两台迁移候选，并与直接候选统一评分。
- 存在常规候选时不启动扩展阶段。
- 常规阶段无解时，三台或更多迁移可产生完整候选。
- 扩展阶段优先最少迁移深度，不返回可以用更多迁移替代的劣解。
- 不存在固定迁移台数上限；合格设备集合和预算决定搜索边界。
- 任一候选迁移不合格设备时被确定性复核拒绝。
- 两个求解器都不能绕过 20,000 变量预算。
- CP-SAT 技术失败时 Beam Search 保持阶段语义；CP-SAT 无解时正确进入扩展阶段。

### 批量与连接

- `count > 10` 和 `count > 100` 不因固定上限被直接拒绝。
- 同规格批次全部放置或全部失败，不出现部分动作。
- 同一候选内 PDU 插口与交换机端口无重复占用。
- 演示种子显式包含 PDU 插口容量；非演示数据缺少容量时返回 `LINK_RESOURCE_INVENTORY_INVALID`。
- 新服务器得到规定数量的电源与网络连接。
- 跨机柜迁移释放旧连接并写入目标连接，设备侧端口和 VLAN 保持不变。
- 目标端口不足、连接冲突或执行中断时设备位置与所有连接整体回滚。
- 计划生成后占用一个目标端口，最终确认返回 `PLAN_STALE`。

### 层内整理

- 删除层底部、中部和顶部设备后均得到稳定紧凑布局。
- 只整理原机柜原挡板层，其他层和机柜保持字节级等价。
- 被动下移不检查 `movable`、关键级别或维护窗口。
- 被删除目标设备仍执行删除安全校验。
- 整理不跨挡板、不覆盖保留 U 位、不改变设备相对顺序。
- 每台设备只会保持原位或移动到更低 U 位。
- 层内下移不更换 PDU 或交换机连接。
- 整理失败时目标设备、连接和所有 U 位全部恢复。

### API、前端与闭环

- 模型超预算返回稳定错误码、变量估算和拆批提示。
- 扩展迁移卡片显示高影响标识、迁移数量和设备清单。
- 一次候选确认执行完整批次，并生成完整审计记录。
- 失效计划被清除，重复点击切换或确认不会重复弹出同一错误。
- 现有直接部署、策略切换、计划选择、回滚和推荐部署回归测试继续通过。

## 验收标准

1. 规划引擎不再使用独立单台迁移兜底；直接部署与最多两台迁移在统一模型中比较。
2. 常规范围完全无解后，系统能在预算内自动寻找三台及以上迁移方案，并优先最少迁移数量。
3. 同规格批次一次确认后全部执行或全部回滚。
4. 跨机柜迁移后设备位置、电源连接和网络连接保持一致，且资源无冲突。
5. PDU 和交换机资源来自显式清单；缺失或越界资源不能通过容量猜测进入方案。
6. 单次部署不再受 10 台、100 台或其他固定台数上限约束；超过 20,000 变量时明确要求拆批。
7. 删除服务器后，其原挡板层内设备稳定向下整理，不跨层、不换连接、不检查被动下移设备的迁移资格。
8. 所有求解候选和删除投影都经过同一确定性安全复核。
9. 计划陈旧、资源不足、模型超预算和执行回滚均有稳定错误码及可操作提示。
10. 新增单元、集成、API 和浏览器测试通过，现有核心回归测试无新增失败。
