# 基于实际入柜现状的部署决策优化设计

## 目标

在现有机房管理演示系统中，把上架推荐从“按层汇总容量”升级为“按现有服务器的固定 U 位和运行约束生成方案”。本轮先使用接近现场分布的仿真数据，后续 NetBox 或采集链路只需提供同一领域模型即可替换数据源。

系统提供“综合最优、集中部署、均衡部署”三种排序策略。管理者设置系统默认策略，并可在单次上架任务中切换。真实 Agent 可以重排合规候选、在受限范围内调整软约束权重，并提出额外的上架、隔板或迁移组合；所有 Agent 结果都必须重新通过确定性规则引擎，且只能在一次最终确认后进入模拟执行。

## 范围

本轮包含：

- 构造 20 个服务器柜的混合现场型仿真占用数据，平均占用约 60%。
- 保存并展示现有服务器的精确起始 U 位和连续占用区间。
- 基于空闲连续区间、容量、业务关系和链路距离生成候选。
- 提供三种可切换的评分策略及系统默认策略。
- 允许真实 Agent 对软决策进行受控干预，并保留确定性降级。
- 迁移仅作为备选方案，必须具备迁移资格、维护窗口、影响说明和回滚动作。
- 在 UI 中对比规则基础方案和 Agent 优化方案，完成最终确认、执行、状态更新和审计闭环。

本轮不包含：

- 真实 NetBox 写入、PDU 实时功率采集或交换机自动配置。
- 对真实服务器执行开关机、迁移、布线或配置变更。
- 允许模型绕过硬约束或直接修改机房事实。

## 决策架构

部署流程固定为：

1. 仓库读取带版本号的机房快照。
2. 固定位置布局器从现有设备的 `start_u` 和 `u_size` 计算占用区间与空闲连续区间。
3. 候选生成器产生直接上架、隔板调整和符合迁移资格的备选动作。
4. 硬约束引擎淘汰所有不合规候选。
5. 策略评分器按本次选择的策略计算基础分并排序。
6. 真实 Agent 读取受限上下文、基础候选、评分证据和风险，返回受控干预结果。
7. Agent 提议经过结构校验、事实校验、动作白名单校验和完整硬约束复核。
8. UI 并列展示基础排序与 Agent 排序，管理者选择一个方案。
9. 最终确认接口比较计划的快照版本与当前状态版本；版本不一致则拒绝执行并要求重新规划。
10. 一次最终确认后由现有模拟执行适配器执行，更新机柜现状、计划状态和审计记录。

规则引擎是最终安全边界。Agent 离线、超时、响应非法或没有通过复核时，系统保留基础候选并标记降级原因，不中断确定性规划闭环。

## 仿真入柜现状

仿真数据覆盖 20 个服务器柜和现有 2 个网络柜。服务器柜平均占用约 60%，同时包含：

- 2 个接近空闲的增长柜；
- 多个普通占用柜；
- 2 个接近 80% 额定功率告警线的机柜；
- 1 个 U 位接近满载且存在碎片的机柜；
- GPU、通用计算、存储和双机业务等不同类型设备；
- 已验证、未知和部分缺失的链路或真实功率状态。

数据生成必须确定性复现，测试与演示重置后得到相同设备、位置和容量。仿真设备不能占用网络柜，也不能覆盖每层唯一的 2U 预留区。

## 领域模型

现有设备增加以下字段：

- `start_u`：设备在机柜内的固定起始 U 位。
- `u_size`：连续占用 U 数；`end_u` 由 `start_u + u_size - 1` 计算，不作为独立可修改事实。
- `business_id`：业务系统标识，用于亲和排序。
- `replica_group`：双机、副本或故障域分散组标识。
- `movable`：是否允许进入迁移备选。
- `criticality`：`normal`、`important` 或 `critical`；`critical` 设备不允许自动生成迁移备选。
- `maintenance_window`：允许迁移的维护时间说明；为空时不可生成可执行迁移方案。
- `data_source` 与各测量字段来源：继续区分仿真、规则、NetBox 和采集值。

机柜继续保存设计功率、重量、端口、隔板、供电支路和接入交换机。供电支路与接入交换机共同参与故障域和链路距离判断。

计划与候选增加：

- `snapshot_version`：生成方案时的状态版本。
- `strategy_id`：`balanced_optimal`、`consolidated` 或 `load_balanced`。
- `baseline_score`、`agent_score` 与分项评分证据。
- `agent_intervention`：模型、权重变化、选择理由、额外动作和复核结果。
- `impact`：迁移影响的设备、业务、维护窗口、步骤和回滚动作。

## 固定 U 位与连续空间

42U 机柜仍分为四层，`L01` 的边界固定，其他层可由隔板定义。每层顶部保留一次 2U，不允许设备占用。

布局器必须把现有设备视为固定区间，检查越界、重叠、跨层和预留区冲突，然后从层内剩余空间计算空闲连续区间。不能再按设备尺寸排序后从层底重新压紧，也不能用“总空闲 U”替代连续空间判断。

新设备的候选动作必须明确 `start_u`。例如一层合计空闲 4U，但空闲空间被拆成两个 2U 区间时，4U 设备不得放入该层。

隔板调整候选只能在不移动或覆盖固定设备、不改变 `L01` 固定边界且每层仍保留一次 2U 的情况下生成。

## 硬约束

三种策略和 Agent 干预共用以下不可覆盖的硬约束：

- 机柜角色必须允许服务器上架。
- 设备必须具有合法的连续 U 区间，且不能重叠、越界或占用层预留区。
- 10U 设备只能放置在 `L01`；本系统支持的单台设备上限仍为 10U。
- 投影额定功率不得超过机柜 10kW 或 20kW 设计上限；达到 80% 产生告警而非自动忽略。
- 投影重量与端口不得超过配置上限。
- 缺失真实功率必须保持 `unknown`，容量判断使用额定功率并显示不确定性。
- 同一 `replica_group` 的设备必须分布在不同故障域；故障域至少包含供电支路与接入交换机。
- 迁移目标设备必须 `movable=true`、`criticality` 不是 `critical`，并且存在维护窗口。
- Agent 只能使用当前快照中的实体和允许的动作类型，不能修改现有设备测量事实、设计容量、状态版本或规则结果。

## 三种评分策略

所有分项统一归一化为 0–100 的惩罚分，分数越低越优。硬约束淘汰发生在评分之前。

### 综合最优 `balanced_optimal`

综合考虑业务距离、连续空间碎片、网络路径、投影容量压力、增长空间和迁移成本。默认偏好同一 `business_id` 的设备位于同柜或邻柜，但 `replica_group` 硬约束优先于亲和偏好。

### 集中部署 `consolidated`

优先使用已启用且仍有安全余量的机柜，惩罚启用空柜，并在不进入告警区的前提下减少剩余碎片。该策略不会为提高集中度而突破 80% 告警线、反亲和要求或硬容量上限。

### 均衡部署 `load_balanced`

优先降低所有机柜和供电分区的最高投影占用率及负载差异，同时比较 U 位、额定功率、重量和端口。对新启用空柜的惩罚最低，但仍保留必要的增长空间。

三套默认权重集中配置并带版本。管理者只能选择系统默认策略和单次任务策略，不直接修改硬约束。Agent 对软权重的倍率限制为 `0.5–2.0`，每项变化必须记录原值、新值和理由。

## 真实 Agent 干预

规则引擎先提供基础候选，Agent 不作为首个或唯一候选生成器。Agent 接收：

- 当前任务的设备事实和选择策略；
- 受限的机柜、容量、业务、故障域与链路摘要；
- 基础候选及分项得分、阻断原因和告警；
- 允许的软权重范围和动作白名单。

Agent 可返回：

- 一个基础候选的重排选择；
- 各软权重在允许范围内的倍率；
- 最多 3 个额外的 `place_device`、`set_dividers` 或 `move_device` 动作组合；
- 对干预理由、业务收益和风险的结构化说明。

服务端必须拒绝未知字段、未知实体、越界权重和其他动作类型。额外动作组合必须重新运行完整投影与硬约束校验。没有通过复核的 Agent 方案只作为被拒绝的审计证据，不进入可选候选列表。

Agent 不可用时返回 `model_status=degraded`，基础候选仍可选择和确认。模型输出、评分变化、复核结果与最终采纳情况写入审计；API Key、认证头和敏感配置不得进入浏览器响应或审计日志。

## 迁移备选

直接上架和安全隔板调整均无候选时，才生成迁移备选。迁移不能默认成为首选，风险等级至少为 `warning`。

每个迁移方案必须包括：

- 被迁移设备、原位置和目标位置；
- 受影响 `business_id`；
- 维护窗口和预估影响；
- 迁移前校验、迁移顺序、迁移后验证；
- 把设备恢复到原位置的回滚动作。

若缺少任一必需信息，方案可以展示为分析建议，但不能进入最终确认。

## 管理界面

上架页面增加系统默认策略展示和单次策略选择器。生成结果包含：

- 当前机柜精确 U 位、预留区、空闲连续区间和碎片情况；
- 规则基础排序与 Agent 优化排序；
- 目标机柜、起止 U 位、投影容量和业务关系；
- 基础分、Agent 分、分项证据、权重变化和 Agent 理由；
- 阻断、告警、不确定性和迁移影响。

选择候选不会修改状态。唯一一次最终确认对话框必须展示策略、最终动作、关键容量变化、Agent 是否干预及所有迁移风险。确认成功后，机柜视图、容量、计划状态和审计同时刷新。

## 并发、异常与降级

- 计划确认必须校验 `snapshot_version`；当前版本已变化时返回“方案已过期”，要求重新生成。
- Agent 超时、网络错误、非法 JSON、未知实体或非法动作统一降级到基础候选，并显示具体错误类别。
- 现有入柜数据发生重叠、越界或预留区冲突时，系统阻止新计划并把数据质量问题作为阻断证据。
- 真实功率缺失不视为 0；继续使用额定功率判断并显示 `unknown` 状态。
- 找不到直接或迁移候选时，返回各机柜的主要阻断原因，而不是空白结果或虚构方案。
- 执行失败时保持原快照、记录失败步骤，并提供可审计的恢复入口。

## 验收标准

1. 同一批新服务器在三种策略下产生不同且可解释的排序。
2. 总空闲 U 足够但没有连续区间时，方案被拒绝并标出碎片证据。
3. 综合最优策略体现业务亲和，且副本被分散到不同故障域。
4. 集中策略优先填充安全的已启用机柜；均衡策略降低最高容量占用及分区差异。
5. Agent 可以在权重边界内重排方案，并展示干预理由。
6. Agent 新增的迁移组合只有在完整复核通过后才进入候选。
7. Agent 离线、超时、非法动作或尝试突破硬约束时，系统稳定降级到基础方案。
8. 迁移候选展示维护窗口、业务影响、操作步骤和回滚路径。
9. 方案生成后改变机柜状态，旧方案在最终确认时失效。
10. 系统只出现一次最终确认；执行后机柜、容量、计划和审计形成交互闭环。
11. 仿真数据重置可复现相同的设备数量、U 位、容量状态和演示场景。
12. 单元、API 和浏览器验收覆盖固定 U 位、三种策略、Agent 干预、迁移资格、状态版本和权限边界。

## 后续真实数据接入

后续 NetBox 适配器负责把机柜、设备、设备槽位、接口、电源口和线缆映射到本设计的领域模型；采集器负责填充实时功率及健康状态。无论数据源如何变化，规划器只消费带版本的规范化快照，规则引擎和最终确认边界保持不变。
