# 手动精确位置部署设计

## 目标

在现有“上架 Agent”模块内移除集中部署和负载均衡的可选功能，并增加单台服务器的手动精确位置部署。用户必须指定机柜、挡板层和起始 U 位；目标位置被占用时直接拒绝，不触发服务器迁移。

## 范围

- 保持现有项目目录、路由、方案确认、执行和审计结构不变。
- 只修改当前上架模块及其直接依赖的规划入口和测试。
- 自动部署固定采用 `balanced_optimal`。
- 保留 `consolidated`、`load_balanced` 的底层定义和历史方案展示兼容，不在当前模块中暴露或提交这两个策略。
- 手动模式只允许部署一台服务器。
- 不修改迁移、取出、告警、拓扑或其他页面逻辑。

## 用户界面

结构化上架表单增加部署模式选择：

- 自动部署：沿用当前综合最优规划，数量保持现有规则。
- 手动精确位置：显示机柜、挡板层、起始 U 位；数量固定为 1 并禁止修改。

机柜列表只包含服务器机柜。选择机柜后根据该机柜的 `layers`/机柜布局生成挡板层选项；切换机柜或挡板层时清空失效的下游选择。自然语言入口和结构化入口都不再显示策略选择器，创建方案时固定提交 `balanced_optimal`。

## 请求契约

继续使用 `POST /api/plans`。手动请求增加以下字段：

```json
{
  "kind": "placement",
  "placement_mode": "manual",
  "strategy_id": "balanced_optimal",
  "target_position": {
    "rack_id": "CAB-03",
    "layer_id": "L02",
    "start_u": 23
  },
  "device": {
    "count": 1
  }
}
```

自动请求使用 `placement_mode: "automatic"`，不提交 `target_position`。

## 后端规划流程

1. 规划入口规范化 `placement_mode`，未提供时按 `automatic` 处理，兼容现有调用方。
2. 手动模式先验证数量和 `target_position` 的结构。
3. 验证目标机柜存在且为服务器机柜、挡板层属于该机柜、起始 U 为正整数、设备区间完全位于挡板层可用范围内。
4. 检查目标区间是否与任一未取消设备重叠。重叠时抛出 `TARGET_POSITION_OCCUPIED`，不进入迁移求解。
5. 构建现有重配置问题时，只给新设备保留该唯一位置，并仅运行直接部署阶段。
6. 沿用现有资源分配和硬约束复核，验证功率、重量、端口、设备高度、10U 层位和物理链路资源。
7. 沿用现有方案持久化、快照版本校验、确认、执行和审计流程。

## 异常契约

- `MANUAL_TARGET_REQUIRED`：手动目标字段缺失。
- `MANUAL_PLACEMENT_COUNT_INVALID`：手动模式数量不为 1。
- `TARGET_RACK_NOT_FOUND`：机柜不存在。
- `TARGET_RACK_NOT_DEPLOYABLE`：目标机柜不是服务器机柜。
- `TARGET_LAYER_NOT_FOUND`：挡板层不存在或不属于目标机柜。
- `TARGET_START_U_INVALID`：起始 U 不是正整数。
- `TARGET_POSITION_OUT_OF_RANGE`：设备占用区间超出挡板层可用范围。
- `TARGET_POSITION_OCCUPIED`：目标区间与现有设备重叠。
- 其余容量和物理资源错误沿用现有稳定错误码。

前端显示错误码及中文解释。后端校验是权威边界，前端校验只用于即时反馈。

## 测试

- 规划单元测试覆盖精确位置成功、数量非法、目标缺失、无效机柜、非服务器机柜、无效挡板层、起始 U 非法、越界及位置占用。
- 位置占用用例包含可迁移设备，并断言不会生成迁移动作。
- API/方案服务测试覆盖手动方案创建、确认和最终设备位置，以及状态版本变化后的确认保护。
- 前端契约测试断言当前模块不含 `consolidated`、`load_balanced`，并包含手动模式和精确位置请求字段。
- 运行现有全量单元测试，确认自动部署、迁移、取出和历史方案展示无回归。
