# Unified Reconfiguration Migration and Layer Compaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-device migration fallback with one atomic same-spec batch reconfiguration planner, allocate exact power/network resources, expand beyond two migrations only when needed, and compact the removed server's original divider layer downward.

**Architecture:** A server-owned reconfiguration problem builder produces schema-v2 devices, position options, link resources, constraints, and an exact variable estimate for both CP-SAT and Beam Search. Both solvers return the same assignment contract, which is converted into complete `place_device` and `move_device` actions and revalidated by the domain engine before plan persistence. Removal uses a separate deterministic compaction module, but shares the same projected-state validation and atomic execution boundary.

**Tech Stack:** Node.js ES modules, Node test runner, Python 3.11+, Google OR-Tools CP-SAT 9.15.6755, JSON repository, browser DOM modules, Playwright 1.61.1.

## Global Constraints

- Only homogeneous batches are supported; mixed device specifications remain out of scope.
- `count` must be a positive integer and has no fixed maximum such as 10 or 100.
- The exact assignment-variable budget is `20_000`; CP-SAT and Beam Search must enforce the same budget and return `MODEL_BUDGET_EXCEEDED` instead of truncating work.
- Normal search compares direct placement with one- and two-device migrations in one score pool.
- Expanded search starts only when normal search has no validated candidate; it begins at three migrations and has no fixed move-count ceiling inside the eligible-device and variable budgets.
- Cross-rack migration requires `movable = true`, non-critical status, and a non-empty maintenance window.
- Every new or cross-rack-moved server receives one PDU outlet and exactly `network_ports` distinct switch ports.
- New device-side network ports are named `eth0` through `eth{network_ports - 1}` with `vlan: null`; existing moved devices preserve known device-port/VLAN pairs and fill missing device ports deterministically with `vlan: null`.
- Existing connection resources remain reserved during solving even if their device moves; execution releases them atomically, but the same candidate does not reuse them.
- A same-spec batch is all-or-nothing, uses one final confirmation, and returns at most four distinct candidates.
- No automatic divider movement is generated by the new planner.
- A removal target retains existing removal eligibility checks; only the remaining devices shifted downward bypass move eligibility.
- Removal compaction stays in the original rack and divider layer, preserves relative order and links, never raises a server, and rolls back with the removal.
- The adapter remains simulated; real power, cabling, switching, and physical movement are out of scope.

- [ ] **Step 3: Implement the canonical resource catalog**

`src/domain/link-resources.js` must use these exact resource-key rules:

```js
const pduOutlet = (number) => `P${String(number).padStart(2, "0")}`;
const switchPort = (number) => `GE0/0/${String(number).padStart(2, "0")}`;

export function buildLinkResourceCatalog(state, { releaseDeviceIds = new Set() } = {}) {
  const pdus = state.topology?.power?.pdus;
  const switches = state.topology?.network?.access_switches;
  if (!Array.isArray(pdus) || !Array.isArray(switches)) {
    throw Object.assign(new Error("Explicit PDU and switch inventories are required"), {
      code: "LINK_RESOURCE_INVENTORY_INVALID",
    });
  }
  const occupiedPower = new Set(state.power_connections
    .filter((item) => !releaseDeviceIds.has(item.device_id))
    .map((item) => `${item.pdu_id}:${item.outlet}`));
  const occupiedNetwork = new Set(state.network_connections
    .filter((item) => !releaseDeviceIds.has(item.device_id))
    .map((item) => `${item.switch_id}:${item.switch_port}`));
  const power_outlets = pdus.flatMap((pdu) => Array.from({ length: Number(pdu.outlet_count) }, (_, index) => ({
    id: `${pdu.id}:${pduOutlet(index + 1)}`,
    pdu_id: pdu.id,
    outlet: pduOutlet(index + 1),
    rack_id: pdu.rack_id,
    source_id: pdu.source_id,
    occupied: occupiedPower.has(`${pdu.id}:${pduOutlet(index + 1)}`),
  })));
  const network_ports = switches.flatMap((item) => Array.from({ length: Number(item.downlink_ports) }, (_, index) => ({
    id: `${item.id}:${switchPort(index + 1)}`,
    switch_id: item.id,
    switch_port: switchPort(index + 1),
    rack_ids: [...item.connected_rack_ids],
    occupied: occupiedNetwork.has(`${item.id}:${switchPort(index + 1)}`),
  })));
  return { power_outlets, network_ports };
}
```

Validate positive integer capacities, unique PDU/switch IDs, rack/source references, connected-rack references, existing connection range, and duplicate resource keys before returning. `materializeConnections` must fill `device_id`, `rack_id`, `source_id`, `data_source: "demo"`, stable `ethN` device ports, and preserve known moved-device VLANs when supplied. `validateLinkResources` returns blocker-shaped issues for duplicate, unknown, wrong-rack, wrong-source, incomplete affected-device, and out-of-range links.

`allocateFirstCompatibleConnections` builds a catalog without releasing existing resources, selects the lexicographically first free PDU outlet in the target rack and the first `device.network_ports` free ports on the rack's configured switch, then calls `materializeConnections`. It throws `LINK_RESOURCE_EXHAUSTED` when either resource class is insufficient and accepts `reservedPowerIds`/`reservedNetworkIds` sets so a batch cannot allocate the same resource twice.

```js
export function planLayerCompaction(state, deviceId) {
  const removed = state.devices.find((item) => item.id === deviceId);
  if (!removed) throw compactionError("DEVICE_NOT_FOUND", deviceId);
  const rack = state.racks.find((item) => item.id === removed.rack_id);
  const layer = deriveLayers(rack).find((item) => item.id === removed.layer_id);
  const peers = state.devices
    .filter((item) => item.id !== deviceId
      && item.status !== "cancelled"
      && item.rack_id === removed.rack_id
      && item.layer_id === removed.layer_id)
    .sort((left, right) => Number(left.start_u) - Number(right.start_u) || left.id.localeCompare(right.id));
  let cursor = layer.start_u;
  const moves = [];
  for (const peer of peers) {
    const target = cursor;
    const end = target + Number(peer.u_size) - 1;
    if (end > layer.usable_end_u || target > Number(peer.start_u)) {
      throw compactionError("COMPACTION_FAILED", deviceId);
    }
    if (target !== Number(peer.start_u)) moves.push({
      device_id: peer.id,
      rack_id: removed.rack_id,
      layer_id: removed.layer_id,
      from_start_u: Number(peer.start_u),
      to_start_u: target,
    });
    cursor = end + 1;
  }
  return moves;
}
```
